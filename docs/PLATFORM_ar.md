# المنصة التعليمية (مدير / معلم / طالب)

طبقة اختيارية فوق Exameow، تعمل **ذاتياً بالكامل** داخل خادم Axum (بدون أي خدمة خارجية). تتوفر في نسخة **الويب/Docker** فقط. بقية ميزات Exameow (التوليد، التدريب، الامتحانات برمز، البحث بالكاميرا…) تعمل كما هي دون حساب.

## الأدوار
| الدور | ما يستطيعه |
|---|---|
| **مدير المنصة** | اعتماد/رفض المعلمين، تعديل كل الحسابات (إيقاف، دور، كلمة مرور)، إدارة المدارس والمعاهد والجامعات وهياكلها ومواردها، اعتماد طلبات تدريس المواد، مراجعة البلاغات، سجل التدقيق، الإحصاءات |
| **المعلم** (بعد الاعتماد) | طلب تدريس مواد، نشر مقالات/ملخصات (مع مرفق)، دورات فيديو، دروس مباشرة، اختبارات من بنوك الأسئلة المولَّدة، تصحيح أسئلة المقال، رؤية النتائج |
| **الطالب** | تصفح المؤسسات والمواد والمعلمين، التسجيل في المواد، متابعة المعلمين، حل الاختبارات، تتبّع التقدّم، تقييم الدورات/المعلمين (المسجّلين فقط)، الإبلاغ عن المحتوى |

## التشغيل
```bash
# Docker (يحفظ البيانات في مجلد /app/data)
export PLATFORM_ADMIN_EMAIL=admin@example.com
export PLATFORM_ADMIN_PASSWORD='كلمة-مرور-قوية-8+'
docker compose up -d --build
```
أو محلياً: `cargo run -p exameow-server` مع نفس المتغيرات.

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PLATFORM_DB_PATH` | `./exameow-platform.db` | قاعدة SQLite للحسابات والمحتوى (منفصلة عن قاعدة الامتحانات التي تُمسح بعد 7 أيام) |
| `PLATFORM_FILES_DIR` | `./platform-files` | مرفقات المعلمين |
| `PLATFORM_KEY_FILE` | بجوار قاعدة البيانات `platform.key` | المفتاح الرئيسي لتشفير الأسرار (مفتاح الذكاء الاصطناعي وSMTP) في «الإعدادات». يُولَّد تلقائياً مرة واحدة بصلاحية 0600 ولا يُستبدل أبداً |
| `PLATFORM_ADMIN_EMAIL` / `PLATFORM_ADMIN_PASSWORD` | — | يُنشأ أول مدير عند الإقلاع **إن لم يوجد مدير**. لا توجد كلمة مرور افتراضية |

## النسخ الاحتياطي والاستعادة (مهم)
**ما تحتويه النسخة:** ملف ZIP واحد فيه (1) **لقطة متسقة** من قاعدة المنصة تُؤخذ والخادم يعمل (`VACUUM INTO`، فلا تُنسخ ملفات `-wal`/`-shm` يدوياً أبداً)، (2) **المفتاح الرئيسي** `platform.key` ليبقى مفتاح الذكاء الاصطناعي المشفّر قابلاً للقراءة بعد الاستعادة، (3) كل **المرفقات**، (4) `manifest.json` بتجزئة SHA-256 لكل ملف وبأعداد صفوف الجداول الرئيسية للتحقق عند الاستعادة. لا تشمل قاعدة «الامتحانات برمز» (`EXAM_DB_PATH`) لأنها مؤقتة وتُمسح بعد 7 أيام.

> ⚠️ النسخة تحتوي **المفتاح الرئيسي مع الأسرار المشفّرة به**: من يملك الملف يستطيع قراءة مفتاح الذكاء الاصطناعي. احفظها في مكان خاص، وشفّرها (مثل `gpg`/`age`) قبل رفعها إلى تخزين لا تثق به.

**كيف تُنشأ**
- **تلقائياً كل ليلة:** أول فحص بعد الساعة 03:00 UTC (يتغير بـ`PLATFORM_BACKUP_HOUR`، أو `off` للإيقاف). يُعوَّض الإيقاف: إن كان الخادم مطفأً وقت الجدولة تُؤخذ النسخة عند أول فحص بعد الإقلاع (مرة واحدة لا مرة لكل ليلة فائتة). أول إقلاع بلا أي نسخة يأخذ نسخة فوراً. إن فشلت نسخة ليلية لا تُعاد قبل مرور 3 ساعات.
- **يدوياً:** من «حالة النظام» أو «الإعدادات»: **«تنزيل نسخة احتياطية»** (تُنشأ ثم تُنزَّل) أو **«إنشاء نسخة على الخادم»**. حد أقصى 6 طلبات في الساعة لكل مدير، ونسخة واحدة في كل مرة (الطلب الثاني أثناء الأولى يأخذ «قيد الإنشاء»). يُسجَّل الإنشاء والتنزيل في سجل العمليات.
- **الاحتفاظ:** آخر **7** نسخ ليلية وآخر **5** يدوية (`PLATFORM_BACKUP_KEEP` / `PLATFORM_BACKUP_KEEP_MANUAL`)، كل نوع على حدة فلا تزيح اليدوية الليلية.
- **المكان:** `PLATFORM_BACKUP_DIR` (الافتراضي `backups/` بجوار قاعدة البيانات؛ في Docker `/app/data/backups` داخل الحجم الدائم). المجلد بصلاحية 0700 والملفات 0600. المجلد هو **مصدر الحقيقة**: عند الإقلاع تُكتشف الملفات غير المسجّلة (مثلاً نسخ أُخذت بعد اللقطة التي استُعيدت) ويُنسى ما حُذف يدوياً، وتُمسح مخلفات أي عملية انقطعت.
- **المساحة:** يُفحص قبل البدء وجود مساحة تكفي قاعدة البيانات مرتين + المرفقات؛ وإلا تفشل النسخة بـ«لا توجد مساحة كافية» وتُسجَّل. تذكّر أن كل نسخة تضم المرفقات كاملة؛ احسب `(حجم القاعدة + المرفقات) × 12`.

**انسخها خارج الخادم** (نسخة على القرص نفسه لا تحميك إن فُقد الخادم):
```bash
# Docker: انسخ المجلد كله إلى جهاز آخر (يوميا عبر cron مثلاً)
docker cp exameow-server:/app/data/backups ./exameow-backups-$(date +%F)
rsync -a ./exameow-backups-* user@backup-host:/srv/exameow/        # أو أي تخزين سحابي
# بدون Docker: rsync -a /path/to/data/backups/ user@backup-host:/srv/exameow/
```
أو نزّل آخر نسخة من الواجهة بعد كل تغيير مهم.

**الاستعادة** (عملية غير متصلة: **أوقف الخادم أولاً**). تتحقق أولاً من النسخة كاملة (تجزئة كل ملف، ثم `integrity_check` لـSQLite، ثم مطابقة أعداد الصفوف مع `manifest.json`) في مجلد مؤقت؛ فإن كانت سليمة تُنقل البيانات الحالية إلى `pre-restore-<الوقت>/` (**لا تُحذف**) وتحل النسخة محلها؛ وإن فشلت أي خطوة تُعاد البيانات السابقة كما كانت. ملف `-wal` القديم لا يُترك بجوار القاعدة المستعادة. بدون `--yes` يكتفي الأمر بالتحقق ولا يغيّر شيئاً.
```bash
# Docker
docker cp exameow-backup-XXXX.zip exameow-server:/app/data/backups/     # إن كانت النسخة خارج الحجم
docker compose stop exameow
docker compose run --rm exameow ./server restore /app/data/backups/exameow-backup-XXXX.zip          # تحقق فقط
docker compose run --rm exameow ./server restore /app/data/backups/exameow-backup-XXXX.zip --yes    # استبدال
docker compose start exameow
# بدون Docker (بنفس متغيرات البيئة التي يعمل بها الخادم)
./exameow-server restore backups/exameow-backup-XXXX.zip --yes
```
بعد الاستعادة تعود الحسابات وكلمات المرور والامتحانات والنتائج والمرفقات والمفتاح الرئيسي كما كانت وقت اللقطة. يبقى الدخول ممكناً بكلمات المرور القديمة. نسخة أُخذت **بعد** اللقطة (في مجلد النسخ) تظهر في القائمة، أما بيانات المنصة نفسها بعد اللقطة فتضيع (للتراجع: `pre-restore-…`). احذف مجلد `pre-restore-…` يدوياً حين تتأكد.

**فقدان المفتاح الرئيسي** (ملف `platform.key` ضاع ولا نسخة): تبقى الحسابات والمحتوى سليمة، وتحتاج فقط إعادة إدخال مفتاح الذكاء الاصطناعي في «الإعدادات».

**ملف `docker-compose.prod.yml`:** صُحِّح ليتضمن الحجم الدائم `exameow-data` ومتغيرات المسارات تحت `/app/data`؛ بدون حجم دائم تضيع كل البيانات والنسخ عند إعادة إنشاء الحاوية.

## حالة النظام (لوحة المدير ← حالة النظام)
صفحة للمدير فقط: إصدار الخادم ومدة التشغيل، حجم قاعدة البيانات والمرفقات (وعددها)، عدد النسخ وحجمها على الخادم، **المساحة الحرة** على القرص (شريط)، الجلسات النشطة، عدد الحسابات؛ مع جدولة النسخ وآخر نسخة ناجحة وآخر محاولة فاشلة (وسببها)، وقائمة النسخ بزر تنزيل لكل منها.
**التنبيهات** (تظهر في أعلى الصفحة وبشارة رقمية على القائمة الجانبية): لا توجد أي نسخة؛ **النسخة متأخرة** (أكثر من 36 ساعة والجدولة الليلية مفعّلة، أو أكثر من 7 أيام إن أُوقفت)؛ **فشلت آخر محاولة** (حتى تنجح نسخة أحدث)؛ **المساحة منخفضة** (أقل من 500 ميغابايت أو 5% من القرص، في مجلد البيانات أو النسخ).
الإصدار المعروض هو إصدار حزمة الخادم (`Cargo.toml`) لا إصدار التطبيق.

## الأمان (ما نُفِّذ)
- كلمات المرور Argon2؛ رموز الجلسة عشوائية 256 بت وتُخزَّن مجزّأة؛ صلاحية 30 يوماً؛ تغيير كلمة المرور يُخرج الأجهزة الأخرى.
- الأدوار تُحدَّد في الخادم فقط؛ كل مسار يتحقق من الدور والحالة. المعلم يبدأ «قيد المراجعة».
- حدّ المحاولات: الدخول (لكل بريد ولكل IP)، التسجيل، البلاغات (20/يوم).
- الإجابات الصحيحة لا تصل للطالب قبل التسليم؛ المؤقت وعدد المحاولات يُفرضان في الخادم.
- النصوص تُعرض كنص عادي (لا HTML)؛ الفيديو يُضمَّن من YouTube/Vimeo فقط عبر روابط يحسبها الخادم؛ الملفات بقائمة امتدادات + فحص البصمة، وتُنزَّل كمرفقات `nosniff`.
- إخفاء تلقائي للمحتوى بعد 3 بلاغات من مستخدمين مختلفين؛ سجل تدقيق لكل قرار إداري.
- رؤوس: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`.

## الإعدادات والذكاء الاصطناعي (لوحة المدير ← الإعدادات)
- **مزوّد الذكاء الاصطناعي:** العنوان والنموذج والمفتاح تُحفظ من الصفحة. المفتاح يُخزَّن **مشفّراً** (AES-256-GCM بالمفتاح الرئيسي `PLATFORM_KEY_FILE`) ولا يُعرض ولا يُعاد للمتصفح أبداً؛ تظهر عبارة «محفوظ ✓» فقط. إن لم يُحفظ شيء تُستخدم متغيرات البيئة `AI_ENDPOINT / AI_API_KEY / AI_MODEL` (لكل حقل على حدة). زر «اختبار الاتصال» يجرّب القيم المكتوبة قبل حفظها.
- **السقوف اليومية:** حد لطلبات التوليد للمنصة كلها وحد لكل مدير (افتراضياً 200 و50)، باليوم بتوقيت UTC؛ الصفر يمنع التوليد. عند بلوغ السقف تُرفض الطلبات برسالة واضحة دون الاتصال بالمزوّد، وإذا فشل المزوّد يُردّ الطلب إلى الرصيد. جدول الاستخدام يعرض اليوم والأيام الأخيرة وحسب المدير.
- **هوية المنصة:** الاسم واللون (يجب أن يكون مقروءاً مع الأبيض، 4.5:1) والشعار (PNG/JPG حتى 512 ك.ب) تُطبَّق فوراً. بلا اسم أو شعار يظهر شعار azlearn الافتراضي.
- **الصفحات القانونية:** نص عادي للخصوصية والشروط؛ روابطها في التسجيل والدخول.
- **المعلمون:** مفتاح «السماح بإنشاء امتحانات» محفوظ الآن ويُطبَّق في منشئ الامتحانات القادم.
- **النسخ الاحتياطي:** انسخ قاعدة البيانات **مع** ملف المفتاح الرئيسي؛ بدونه تُفقد الأسرار المخزنة (تُعاد كتابتها فقط).

## بنك الأسئلة (لوحة المدير ← بنك الأسئلة)
- لكل مادة بنكها: نوع السؤال، النص، الخيارات، الإجابة، الشرح، الوحدة، الصعوبة، الوسوم. البحث يتجاهل التشكيل واختلاف الهمزات، والتصفية بالنوع والصعوبة والوحدة والوسم، مع الأرشفة (تُخفي السؤال دون حذفه) والحذف النهائي والتحديد الجماعي.
- **التكرار تنبيه لا منع:** السؤال بنفس النص (بعد توحيد الهمزات والمسافات) في المادة نفسها يُحفظ مع تنبيه؛ وفي الاستيراد يمكن تخطي المكرر.
- **الاستيراد:** من بنوك هذا المتصفح (التي أنشأتها أداة التوليد/التمرين)، أو من ملف CSV/XLSX بنفس صيغة الأداة القديمة. تُفحص الأسئلة واحداً واحداً؛ المرفوض يُعرض برقمه وسببه ولا يمنع الباقي. الإجابات تُوحَّد (مثل `b` أو `A, C` أو «صحيح/False»).
- حذف سؤال من البنك أو تعديله **لا يغيّر** أي امتحان سبق إنشاؤه (الامتحان يأخذ نسخة ثابتة).

## الامتحانات (لوحة المدير ← الامتحانات)
- **المنشئ بثلاث خطوات:** (1) المصدر: اختر المؤسسة والمادة ثم أضف أسئلة بأي مزيج من: التوليد بالذكاء الاصطناعي من ملف (يُحسب من سقفك اليومي، مع خيار حفظ الأسئلة المولَّدة في بنك المادة)، أو الاختيار من بنك المادة، أو الكتابة اليدوية بالأنواع الخمسة. (2) المراجعة: تعديل وحذف وترتيب (أزرار ↑↓) ودرجة لكل سؤال (الافتراضي 1) مع مجموع الدرجات وعدد كل نوع، وتحقق فوري يعلّم السؤال غير الصالح ويمنع الحفظ حتى يُصلَح. (3) الإعدادات: العنوان والوصف والمدة والمحاولات (1–10) ونافذة الفتح والإغلاق وترتيب الأسئلة/الخيارات العشوائي ودرجة النجاح وموعد إظهار النتيجة وإظهار الإجابات، مع **معاينة** كما يراها الطالب (دون إنشاء محاولة)، ثم «حفظ كمسودة» أو «نشر».
- **لقطة ثابتة:** الامتحان ينسخ الأسئلة عند إنشائه؛ تعديل البنك أو حذف سؤال منه لا يغيّر امتحاناً قائماً.
- **دورة الحياة:** مسودة ← منشور ← مغلق ← مؤرشف. الإغلاق يدوي أو تلقائي عند موعد الإغلاق (يظهر مغلقاً دون تغيير الحالة). «نسخ» ينتج مسودة جديدة بلا مواعيد. «إعادة فتح» تُعيد المغلق منشوراً (مدّد الإغلاق أولاً إن كان قد فات). الأرشفة للمسودات والمغلقة فقط؛ أغلق المنشور أولاً.
- **قواعد التعديل:** قبل أي محاولة كل شيء قابل للتعديل. بعد أول محاولة تُجمَّد الأسئلة والدرجات والمدة وموعد الفتح والترتيب العشوائي؛ المسموح: العنوان والوصف وتمديد الإغلاق وإظهار الإجابات وموعد النتيجة ودرجة النجاح وزيادة المحاولات.
- **الحذف:** امتحان بلا محاولات يُحذف بتأكيد عادي؛ وله محاولات يتطلب **كتابة عنوانه بالضبط** ويُسجَّل في سجل العمليات (والأرشفة أفضل).
- **امتحانات المعلمين:** تظهر في القائمة للإشراف فقط (إغلاق/أرشفة/حذف/نسخ)، ولا يعدّلها المدير. المدير يصحّح المقالات في امتحاناته (وفي امتحانات المعلمين عند الحاجة).
- الترتيب العشوائي ودرجة النجاح وموعد إظهار النتيجة تُطبَّق على أداء الطلاب (انظر «أداء الامتحان»).

## أداء الامتحان (الطالب)
- **الترتيب العشوائي:** يحسبه الخادم عند بدء كل محاولة (ترتيب الأسئلة و/أو الخيارات) ويُخزَّن، فيعود الطالب لنفس الترتيب عند إعادة فتح المحاولة. التصحيح يتم **بنص الخيار** لا بموضع الحرف على الشاشة. خيارات صح/خطأ لا تُبدَّل.
- **الحفظ التلقائي:** تُحفظ الإجابات في الخادم بعد كل تعديل (بتأخير 5 ثوانٍ) وكل 30 ثانية، فتُستأنف المحاولة على أي جهاز. إن انتهى الوقت والمتصفح غائب تُسلَّم تلقائياً الإجابات المحفوظة آخر مرة (وتُحتسب بزمن الانتهاء)؛ وإن لم يُحفظ شيء تُعلَّم المحاولة «منتهية» بدرجة صفر. تُسوَّى المحاولات المتأخرة عند فتح النتائج وكل ساعة.
- **مغادرة التبويب:** تُسجَّل كل مغادرة للصفحة (بما فيها إعادة التحميل) ويراها المصحّح والمدير فقط؛ لا منع ولا إنهاء تلقائي.
- **موعد إظهار النتيجة:** إن اختير «بعد الإغلاق» لا يرى الطالب الدرجة ولا التفاصيل ولا النجاح/الرسوب حتى يُغلق الامتحان (يدوياً أو بحلول موعد الإغلاق)؛ يخفيها الخادم نفسه لا الواجهة. المدير والمصحّح يرون كل شيء فوراً.
- **درجة النجاح:** نسبة مئوية من مجموع الدرجات (شاملة: 60% تنجح عند 60% تماماً). لا يُحكم بنجاح أو رسوب قبل تصحيح المقالات. تظهر أعداد الناجحين في صفحة النتائج.
- **اختبار الحمل:** `cargo build --release -p exameow-server && node scripts/loadtest-exam.cjs` (300 طالب متزامن، امتحان من 40 سؤالاً). نتيجة آخر تشغيل على 4 أنوية: 0 أخطاء، كل الدرجات مطابقة، بدء متزامن p95 ≈ 0.35 ث، حفظ تلقائي p95 ≈ 0.3 ث، تسليم p95 ≈ 0.36 ث، ذاكرة الخادم مستقرة (~0.6 غ.ب، معظمها من تجزئة كلمات المرور عند إنشاء الحسابات دفعة واحدة).

## التصحيح والنتائج والتصدير
- **من يصحّح ويرى النتائج:** المدير دائماً؛ المعلم المالك لامتحانه؛ وفي **امتحانات المدير** (التي بلا معلم) كل معلم **معتمد للمادة**. زميل معتمد للمادة نفسها لا يصل إلى امتحان معلم آخر. الطالب لا يصل إلى أي من هذا.
- **«بحاجة تصحيح»:** صفحة تجمع كل الإجابات المقالية غير المصحَّحة عبر الامتحانات (الأقدم أولاً)، وتظهر شارة بعددها في القائمة الجانبية للمدير وعلى الصفحة الرئيسية للمعلم. شاشة التصحيح السريع تعرض السؤال والإجابة النموذجية ثم إجابات الطلاب، لكل إجابة خانة درجة وأزرار «كاملة/صفر»، وزر Enter ينقل للخانة التالية، و«حفظ الدرجات» يحفظ الصفحة كلها في عملية واحدة (إما الكل أو لا شيء). يمكن تصحيح درجة سبق تصحيحها (للإجابات المكتوبة فقط)؛ الإجابة الفارغة تبقى صفراً. يُشعَر الطالب مرة واحدة عند اكتمال تصحيح محاولته.
- **لوحة النتائج:** عدد المؤدّين والنسبة من المسجّلين، المتوسط والوسيط والأعلى والأدنى، الناجحون والراسبون، من ينتظر التصحيح، متوسط الزمن، **توزيع الدرجات** في خمس فئات (100% في الأخيرة، والحد الفاصل يذهب للأعلى)، و**تحليل الأسئلة**: نسبة الإجابة الصحيحة لكل سؤال مع علامة «ضعيف» (<30%) و«سهل» (>90%) — لا تُعلَّم الأسئلة بأقل من 5 إجابات مصحَّحة. إحصاءات الدرجات تعتمد **أفضل محاولة مصحَّحة** لكل طالب؛ ونسب الأسئلة تشمل كل المحاولات.
- **جدول الطلاب:** الاسم، الدرجة والنسبة، النتيجة (ناجح/راسب/بانتظار التصحيح/منتهية)، زمن الأداء، مغادرات التبويب، وقت التسليم، رقم المحاولة؛ مع ترتيب بأي عمود وتصفية بالنتيجة وبحث بالاسم وترقيم. **البريد الإلكتروني للطلاب يراه المدير فقط.**
- **التصدير:** ملف **XLSX** (ورقة «النتائج» وورقة «الأسئلة»، من اليمين لليسار) أو **CSV** (النتائج أو الأسئلة) بترميز UTF-8 يفتحه Excel بالعربية. أسماء الملفات لاتينية. أي خلية نصية تبدأ بـ `= + - @` تُحيَّد في CSV (إضافة `'` في أولها) منعاً لحقن الصيغ من أسماء الطلاب؛ وXLSX يخزّن النصوص كنصوص فلا تُنفَّذ أبداً. التصدير مقيّد بـ10 مرات في الدقيقة ويُسجَّل في سجل العمليات.

## الإشعارات والتذكيرات
- **الإشعارات داخل التطبيق** فقط (لا بريد حتى يُضاف SMTP). تُخزَّن بنوع وبيانات وتُعرض بلغة الواجهة الحالية.
- **تذكير الإغلاق (`exam_closing`):** يصل الطالب المسجَّل في المادة **مرة واحدة** حين يقترب إغلاق امتحان مفتوح إلى **24 ساعة**، بشرط ألا يكون بدأه أو أدّاه (أي محاولة بأي حالة تعني «لم يعد بحاجة للتذكير»). لا يصل التذكير قبل مضي **6 ساعات** على إعلان الامتحان، فلا يلتصق بإشعار «امتحان جديد»؛ ولذلك لا تذكير لنافذة أقصر من 6 ساعات. من سُجِّل في المادة متأخراً يُذكَّر مرة واحدة في الفحص التالي. لا يُذكَّر أحد قبل فتح الامتحان ولا بعد إغلاقه، ولا في مادة مجمّدة أو معلم موقوف.
- **«نتيجتك متاحة» (`exam_results`):** للامتحانات ذات الإظهار «بعد الإغلاق»؛ حين يُغلق الامتحان (يدوياً أو بحلول موعده) يُشعَر كل طالب سلّم محاولته قبل الإغلاق، والرابط يفتح أحدث محاولة له. من سلّم بعد الإغلاق رأى نتيجته فوراً فلا إشعار له. إعادة فتح الامتحان (أو تمديد موعد انتهى) تُعيد إخفاء النتائج، فيُشعَر الطلاب مرة أخرى عند الإغلاق التالي.
- **إشعار «تم تصحيح اختبارك»** لا يُرسَل أثناء حجب النتيجة؛ إشعار الإتاحة يغطّيه.
- **كيف تعمل:** حلقة في الخادم كل **60 ثانية** (وأول فحص فور الإقلاع). كل فحص يحسب المستحَق من حالة البيانات الحالية، لا من «ما حدث منذ الفحص السابق»، لذلك **إن أُوقف الخادم** يُعوَّض كل ما فات عند أول فحص بعد الإقلاع (تذكير الإغلاق ما دام الامتحان لم يُغلق؛ إتاحة النتائج لما أُغلق خلال آخر **14 يوماً**). جدول `exam_reminders` يمنع التكرار؛ سطر العلامة والإشعار يُكتبان في معاملة واحدة فلا يضيع إشعار ولا يتكرر عند الانقطاع.
- لا إعداد لتغيير مدة التذكير في هذا الإصدار (24 ساعة ثابتة).

## قيود معروفة
- لا تأكيد بريد ولا «نسيت كلمة المرور» (يتطلبان SMTP). المدير يستطيع إعادة تعيين كلمة مرور أي حساب.
- رمز الجلسة في `localStorage` (يتعرّض لو وُجدت ثغرة XSS؛ النصوص كلها مُهرَّبة).
- عنوان العميل لحدّ المحاولات يُقرأ من `X-Forwarded-For`؛ ضع الخادم خلف وكيل عكسي موثوق ولا تعرّضه مباشرة.
- SQLite يكفي لآلاف المستخدمين النشطين؛ الكتابة متسلسلة (والنسخ الاحتياطي يحجز الاتصال لحظة أخذ لقطة القاعدة فقط، ثم يضغط ويكتب خارج القفل). للأحجام الأكبر يُنقل إلى PostgreSQL (المنطق معزول في `packages/server/src/platform*.rs`).
- الفيديو لا يُرفع للخادم؛ يُضمَّن من الخارج.
- نسخ Cloudflare وTauri لا تُظهر المنصة ما لم يُضبط `VITE_PLATFORM_API` على خادم المنصة.
- اسم الملف العربي عند التنزيل قد يظهر «download» في Chromium بلا واجهة (اختبارات آلية)؛ المتصفحات العادية والأسماء اللاتينية سليمة.
